1.1 ความหมายและความสำคัญของปัญหา
================================================================================

ในปัจจุบัน สถาบันอุดมศึกษาหลายแห่งยังขาดระบบที่เป็นช่องทางกลางสำหรับการรับเรื่องร้องเรียนด้านสถานที่ เช่น ปัญหาน้ำท่วม ไฟฟ้าขัดข้อง ระบบคอมพิวเตอร์หรือเว็บไซต์ใช้งานไม่ได้ ซึ่งมักทำให้ผู้ใช้บริการต้องโพสต์ปัญหาลงบนสื่อสังคมออนไลน์แทน ส่งผลให้การแก้ไขปัญหาล่าช้าและขาดการติดตามอย่างเป็นระบบ อีกทั้งยังส่งผลต่อภาพลักษณ์ของสถาบัน

เพื่อแก้ไขปัญหาดังกล่าว จึงได้มีการพัฒนาระบบรับเรื่องร้องเรียนด้านสถานที่ที่สามารถใช้งานได้หลายกลุ่มผู้ใช้งาน ทั้งนักศึกษา คณาจารย์ บุคลากร และบุคคลภายนอก โดยมีฟังก์ชันหลัก เช่น การจัดหมวดหมู่เรื่องร้องเรียน การมอบหมายงาน การติดตามสถานะ และการรายงานสถิติ

อย่างไรก็ตาม เพื่อเพิ่มประสิทธิภาพและความสะดวกสบายมากขึ้น ระบบยังได้ขยายความสามารถเพิ่มเติม ได้แก่
• ช่องทาง LINE Bot เพื่อให้ผู้ใช้งานสามารถแจ้งปัญหาผ่านแอปพลิเคชันที่คุ้นเคย
• ระบบประชาสัมพันธ์ข่าวสาร เช่น การแจ้งกิจกรรมเก็บขยะแลกชั่วโมงจิตอาสา หรือแจ้งปิดปรับปรุงระบบ

ระบบนี้จะถูกพัฒนาให้อยู่ในรูปแบบ Template ที่สามารถประยุกต์ใช้กับมหาวิทยาลัยอื่น ๆ ได้ โดยเพียงปรับข้อมูลพื้นฐานที่เกี่ยวข้อง


1.2 วัตถุประสงค์ของโครงงาน
================================================================================

วัตถุประสงค์ทั่วไป
--------------------------------------------------------------------------------
เพื่อพัฒนา web application ระบบรับเรื่องร้องเรียนด้านสถานที่ในสถาบันอุดมศึกษา ที่เป็นศูนย์กลางการแจ้งปัญหาและติดตามการแก้ไข สามารถเพิ่มประสิทธิภาพในการสื่อสารระหว่างผู้ร้องเรียนกับหน่วยงานที่เกี่ยวข้อง และช่วยยกระดับคุณภาพการจัดการสิ่งอำนวยความสะดวกภายในมหาวิทยาลัย

วัตถุประสงค์เฉพาะ
--------------------------------------------------------------------------------
1. เพื่อจัดทำระบบที่เปิดโอกาสให้ผู้ใช้ทุกกลุ่ม ได้แก่ นักศึกษา คณาจารย์ บุคลากร และบุคคลภายนอก สามารถส่งเรื่องร้องเรียนหรือรายงานปัญหาที่พบได้อย่างสะดวก
2. เพื่อพัฒนาฟังก์ชันการติดตามสถานะและความคืบหน้าของเรื่องร้องเรียน ทำให้ผู้ใช้สามารถตรวจสอบได้ว่าปัญหาของตนอยู่ในขั้นตอนใด
3. เพื่อจัดหมวดหมู่และลำดับความสำคัญของเรื่องร้องเรียน ช่วยให้หน่วยงานที่เกี่ยวข้องสามารถบริหารจัดการและแก้ไขปัญหาได้อย่างมีประสิทธิภาพ
4. เพื่อสร้างระบบแจ้งเตือนและการมอบหมายงานไปยังเจ้าหน้าที่หรือหน่วยงานที่รับผิดชอบโดยอัตโนมัติ
5. เพื่อจัดทำรายงานและสถิติการร้องเรียน เพื่อใช้เป็นข้อมูลสำหรับการวางแผน ปรับปรุง และพัฒนาสิ่งอำนวยความสะดวกของสถาบัน


1.3 ขอบเขตของระบบ
================================================================================

ระบบรับเรื่องร้องเรียนในสถาบันอุดมศึกษา เป็นแอปพลิเคชันเว็บไซต์ที่พัฒนาขึ้นเพื่อรองรับการรับเรื่องร้องเรียนเกี่ยวกับสถานที่และสิ่งอำนวยความสะดวกภายในมหาวิทยาลัย โดยสามารถใช้งานได้ทั้งบุคคลภายในและภายนอกสถาบันอย่างเป็นระบบ มีประสิทธิภาพ และโปร่งใส

ครอบคลุม
--------------------------------------------------------------------------------
1. ผู้ใช้งานระบบ
   • ผู้ร้องเรียน ได้แก่ นักศึกษา คณาจารย์ บุคลากร และบุคคลภายนอก (เช่น ผู้ปกครอง ศิษย์เก่า ผู้มาติดต่อ) สามารถส่งเรื่องร้องเรียนผ่านระบบได้
   • เจ้าหน้าที่ผู้รับผิดชอบ ได้แก่ ฝ่ายอาคารสถานที่ ฝ่ายรักษาความปลอดภัย ฝ่ายซ่อมบำรุง ที่จะได้รับการมอบหมายงานและดำเนินการแก้ไข
   • ผู้ดูแลระบบ (Admin) ได้แก่ ศูนย์สารสนเทศ ทำหน้าที่จัดการผู้ใช้ กำหนดสิทธิ์การเข้าถึง และดูแลภาพรวมของระบบ

2. ฟังก์ชันหลักของระบบ
   • การรับเรื่องร้องเรียนและรายงานปัญหาจากผู้ใช้
   • การจัดหมวดหมู่และลำดับความสำคัญของเรื่องร้องเรียน
   • การมอบหมายงานและแจ้งเตือนไปยังหน่วยงานที่เกี่ยวข้อง
   • การติดตามสถานะและความคืบหน้าของเรื่องร้องเรียน
   • การแสดงผลรายงานและสถิติเรื่องร้องเรียนเพื่อการบริหารจัดการ
   • การจัดการข้อมูลผู้ใช้และสิทธิ์การเข้าถึง

3. ลักษณะของระบบ
   • พัฒนาเป็นเว็บเซอร์วิส (Web Service) ที่สามารถใช้งานได้ผ่านคอมพิวเตอร์และอุปกรณ์พกพา
   • รองรับการใช้งานแบบ Responsive Design
   • ออกแบบให้สามารถปรับเปลี่ยนเป็น Template เพื่อใช้งานในมหาวิทยาลัยอื่นๆ ได้

ไม่ครอบคลุม
--------------------------------------------------------------------------------
• ระบบการเงินและการบัญชี
• ระบบสารสนเทศนักศึกษา (Student Information System)
• ระบบจัดการการเรียนการสอน (Learning Management System)
• ระบบส่งคำขอด้านเอกสารต่าง ๆ


1.4 เครื่องมือที่เกี่ยวข้องกับโครงงาน (Hardware/Software)
================================================================================

ฮาร์ดแวร์ (Hardware)
--------------------------------------------------------------------------------
• คอมพิวเตอร์สำหรับการพัฒนา
  - CPU: Intel Core i5 หรือเทียบเท่า
  - RAM: 8 GB ขึ้นไป
  - Storage: 256 GB SSD ขึ้นไป
  - ระบบปฏิบัติการ: Windows 10/11 หรือ macOS

• อุปกรณ์สำหรับทดสอบระบบ
  - สมาร์ทโฟน (Android/iOS)
  - แท็บเล็ต
  - คอมพิวเตอร์

ซอฟต์แวร์ (Software)
--------------------------------------------------------------------------------

▸ เครื่องมือและเฟรมเวิร์กสำหรับการพัฒนา Frontend
  • React (v19.1.1)
    - ไลบรารี JavaScript สำหรับสร้าง User Interface แบบ Component-based

สรุป Stack เทคโนโลยีหลักที่ใช้
--------------------------------------------------------------------------------
• Frontend: React 19 + Vite + Tailwind CSS + DaisyUI
• Backend: Node.js + Express.js + MongoDB (Mongoose)

• State Management & Forms: React Hook Form
• Charts & Visualization: Recharts
• Animations: Framer Motion
• HTTP Client: Axios
• Authentication: JWT + bcryptjs
• File Management: Multer (Upload), file-saver (Download), XLSX (Excel)
• Testing: Mocha + Chai + Supertest + Mochawesome
• Development Tools: Nodemon, ESLint, Git/GitHub


1.5 ประโยชน์ที่คาดว่าจะได้รับ
================================================================================

1. ผู้ใช้บริการ (นักศึกษา คณาจารย์ บุคลากร และบุคคลภายนอก)
--------------------------------------------------------------------------------
• มีช่องทางที่เป็นระบบในการแจ้งปัญหาหรือร้องเรียนด้านสถานที่
• สามารถติดตามความคืบหน้าและทราบสถานะของเรื่องร้องเรียนได้อย่างโปร่งใส
• ลดความยุ่งยากในการค้นหาหน่วยงานที่เกี่ยวข้อง เนื่องจากระบบจะมอบหมายอัตโนมัติ
• มีหลายช่องทางในการแจ้งปัญหา เช่น เว็บไซต์และ LINE Bot
• ใช้งานสะดวกผ่านระบบระบุตำแหน่งที่ชัดเจน (อาคาร > ชั้น > ห้อง)
• เข้าถึงข่าวสารและกิจกรรมของสถาบันได้ง่ายผ่านระบบประชาสัมพันธ์

2. หน่วยงานที่เกี่ยวข้อง (ฝ่ายอาคารสถานที่ ฝ่ายรักษาความปลอดภัย ฝ่ายซ่อมบำรุง)
--------------------------------------------------------------------------------
• สามารถรับทราบปัญหาได้อย่างรวดเร็ว ตรงจุด และมีรายละเอียดชัดเจน
• ช่วยจัดลำดับความสำคัญของงานตามประเภทและความเร่งด่วนได้อย่างมีประสิทธิภาพ
• ลดความสับสนในการประสานงาน และเพิ่มประสิทธิภาพในการแก้ไขปัญหา
• ได้รับข้อมูลปัญหาที่ชัดเจนพร้อมตำแหน่งที่แม่นยำ (อาคาร ชั้น ห้อง)
• สามารถอัพเดทความคืบหน้าและสื่อสารกับผู้ร้องเรียนได้โดยตรงผ่านระบบ
• สามารถจัดการงานได้ตามลำดับความสำคัญและติดตามสถานะได้แบบ Real-time

3. ผู้ดูแลระบบ (ฝ่ายศูนย์สารสนเทศ)
--------------------------------------------------------------------------------
• สามารถบริหารจัดการผู้ใช้งาน กำหนดสิทธิ์การเข้าถึง และดูแลภาพรวมของระบบได้อย่างสะดวก
• สามารถจัดทำรายงานและสถิติเรื่องร้องเรียนผ่าน Dashboard ที่แสดงข้อมูลอย่างครบถ้วน
• วิเคราะห์แนวโน้มและปัญหาที่เกิดขึ้นบ่อยเพื่อนำไปใช้ในการวางแผนปรับปรุงระบบบริหารจัดการ
• ประชาสัมพันธ์ข่าวสารและกิจกรรมไปยังผู้ใช้งานได้อย่างมีประสิทธิภาพ
• Export ข้อมูลเพื่อนำเสนอผู้บริหารหรือใช้ในการวิเคราะห์เชิงลึก

4. สถาบันอุดมศึกษาโดยรวม
--------------------------------------------------------------------------------
• มีระบบจัดการเรื่องร้องเรียนที่ทันสมัย ครบวงจร และเข้าถึงง่าย
• ยกระดับคุณภาพการให้บริการและการจัดการสิ่งอำนวยความสะดวก
• ลดข้อร้องเรียนที่ซ้ำซ้อนและสามารถตรวจสอบย้อนหลังได้
• สร้างภาพลักษณ์ที่ดีด้านความใส่ใจต่อผู้เรียน บุคลากร และผู้มาติดต่อ
• มีฐานข้อมูลสำหรับการวิเคราะห์และวางแผนการปรับปรุงในระยะยาว
• สามารถนำระบบไปขยายผลหรือประยุกต์ใช้ในมหาวิทยาลัยอื่นๆ ได้ง่าย เนื่องจากพัฒนาในรูปแบบ Template
• เพิ่มประสิทธิภาพในการบริหารจัดการทรัพยากรและงบประมาณด้านการซ่อมบำรุง

2.1 การวิเคราะห์และออกแบบระบบ
================================================================================

การศึกษาและเปรียบเทียบระบบที่มีอยู่
--------------------------------------------------------------------------------
จากการศึกษาและเปรียบเทียบระบบรับเรื่องร้องเรียนที่มีอยู่ในปัจจุบัน พบว่ามีระบบที่น่าสนใจหลายระบบ ดังนี้

• Traffy Fondue ของกรุงเทพมหานคร
  มีฟังก์ชันรับเรื่องร้องเรียนผ่านหลายช่องทาง สามารถปักหมุดตำแหน่งที่เกิดปัญหาบนแผนที่ได้ และติดตามสถานะได้แบบโปร่งใส

• ศูนย์บริการประชาชน กระทรวงแรงงาน
  มีระบบฟอร์มออนไลน์สำหรับส่งเรื่องร้องทุกข์ ติดตามผล และแสดงสถานะการดำเนินงาน

• ระบบร้องทุกข์ผู้บริโภค (OCPB)
  เน้นกระบวนการจัดการเรื่องร้องเรียนที่เกี่ยวข้องกับผู้บริโภค โดยมีระบบจัดหมวดหมู่และส่งต่อให้หน่วยงานที่เกี่ยวข้อง

• ระบบร้องเรียนของกระทรวงสาธารณสุข (DDC MOPH)
  มีฟังก์ชันสำหรับประชาชนทั่วไปในการแจ้งปัญหาด้านสุขภาพและการบริการ พร้อมระบบติดตามและรายงานผล

จากการวิเคราะห์จุดแข็งและข้อจำกัดของระบบเหล่านี้ ระบบที่กำลังพัฒนาสำหรับสถาบันอุดมศึกษาจะเน้นไปที่การรับเรื่องร้องเรียนด้านสถานที่และสิ่งอำนวยความสะดวก โดยมีคุณสมบัติเด่นเพิ่มเติม ดังนี้

• รองรับการแจ้งปัญหาผ่านเว็บไซต์และ LINE Bot
• รองรับการระบุตำแหน่งปัญหา ผ่านแผนที่และ Dropdown (อาคาร > ชั้น > ห้อง)
• มีระบบประชาสัมพันธ์ข่าวสารและกิจกรรมของสถาบัน
• มีระบบรายงานและ Dashboard สำหรับวิเคราะห์ข้อมูล
• พัฒนาในรูปแบบ Template ที่สามารถประยุกต์ใช้กับมหาวิทยาลัยอื่นได้

การออกแบบระบบ
--------------------------------------------------------------------------------
การออกแบบระบบจะอ้างอิงตามแนวคิด User-Centered Design โดยคำนึงถึงความสะดวกของผู้ใช้งานเป็นหลัก และมีการแบ่งกลุ่มผู้ใช้งาน (User Roles) ดังนี้

1. ผู้ร้องเรียน (User)
   นักศึกษา คณาจารย์ บุคลากร และบุคคลภายนอก

2. เจ้าหน้าที่ผู้รับผิดชอบ (Staff/Officer)
   ฝ่ายอาคารสถานที่ ฝ่ายซ่อมบำรุง ฝ่ายรักษาความปลอดภัย

3. ผู้ดูแลระบบ (Admin)
   จัดการข้อมูลผู้ใช้งาน กำหนดสิทธิ์ และดูแลระบบโดยรวม

สถาปัตยกรรมระบบ
--------------------------------------------------------------------------------
ระบบถูกออกแบบเป็น Web Service + LINE Bot Integration โดยมีโครงสร้างการทำงานดังนี้

• Frontend
  React + Vite + Tailwind CSS (รองรับ Desktop และ Mobile)

• Backend
  Node.js + Express.js (เชื่อมต่อฐานข้อมูลและจัดการ API)

• Database
  MongoDB (จัดเก็บข้อมูลผู้ใช้ เรื่องร้องเรียน และสถานะการดำเนินงาน)

• LINE Integration
  LINE Messaging API สำหรับ LINE Bot

• Notification Service
  Firebase Cloud Messaging สำหรับ Push Notification

• Location System
  ระบบแผนที่และ Dropdown แบบลำดับชั้น

ข้อกำหนดเชิงหน้าที่ (Functional Requirements)
--------------------------------------------------------------------------------
แบ่งตามกลุ่มผู้ใช้งานระบบ ดังนี้

1. ผู้ร้องเรียน (User) - นักศึกษา คณาจารย์ บุคลากร และบุคคลภายนอก
   
   1.1 การเข้าสู่ระบบและจัดการโปรไฟล์
       - ลงทะเบียนบัญชีใหม่ (สำหรับบุคคลภายนอก)
       - เข้าสู่ระบบด้วยบัญชีภายในสถาบัน (Single Sign-On)
       - จัดการโปรไฟล์ส่วนตัว (แก้ไขข้อมูล เปลี่ยนรหัสผ่าน)
       - เชื่อมต่อบัญชีกับ LINE Bot
   
   1.2 การส่งเรื่องร้องเรียน
       - แจ้งเรื่องร้องเรียนผ่านฟอร์มออนไลน์
       - เลือกหมวดหมู่ปัญหา (เช่น ไฟฟ้า, ประปา, อาคารสถานที่, IT)
       - ระบุตำแหน่ง (อาคาร > ชั้น > ห้อง) หรือปักหมุดบนแผนที่
       - แนบรูปภาพประกอบ (สูงสุด 5 รูป)
       - ระบุระดับความเร่งด่วน (ปกติ, ด่วน, ด่วนมาก)
       - ส่งเรื่องร้องเรียนผ่าน LINE Bot
   
   1.3 การติดตามเรื่องร้องเรียน
       - ดูรายการเรื่องร้องเรียนของตนเอง
       - ติดตามสถานะเรื่องร้องเรียน (รอดำเนินการ, กำลังดำเนินการ, เสร็จสิ้น, ยกเลิก)
       - รับการแจ้งเตือนเมื่อมีความคืบหน้า (Email / LINE / Push Notification)
       - ดูความคิดเห็นและอัพเดทจากเจ้าหน้าที่
       - ให้คะแนนและรีวิวการให้บริการหลังเสร็จสิ้นงาน
       - ดู Dashboard ส่วนตัว
         > สถิติเรื่องร้องเรียนของตนเอง
         > จำนวนตามสถานะ
         > กราฟเรื่องร้องเรียนรายเดือน
         > การเปรียบเทียบข้อมูลระหว่างช่วงเวลา
       - ดูระยะเวลาเฉลี่ยในการแก้ไขปัญหา
   
   1.4 การรับข่าวสาร
       - ดูประกาศและข่าวสารของมหาวิทยาลัยบนหน้าแรก
       - รับการแจ้งเตือนประกาศสำคัญ
       - ดูประวัติประกาศย้อนหลัง

2. เจ้าหน้าที่ผู้รับผิดชอบ (Staff/Officer) - ฝ่ายอาคารสถานที่ ฝ่ายซ่อมบำรุง ฝ่ายรักษาความปลอดภัย
   
   2.1 การเข้าสู่ระบบและจัดการโปรไฟล์
       - เข้าสู่ระบบด้วยบัญชีที่ Admin สร้างให้
       - จัดการโปรไฟล์ส่วนตัว (แก้ไขข้อมูล เปลี่ยนรหัสผ่าน)
   
   2.2 การรับและจัดการงาน
       - รับการแจ้งเตือนเมื่อมีงานใหม่ที่ได้รับมอบหมาย (Email / LINE / Push Notification)
       - ดูรายการงานทั้งหมดที่ได้รับมอบหมาย
       - กรองงานตามสถานะและระดับความเร่งด่วน
       - ดูรายละเอียดเรื่องร้องเรียนพร้อมรูปภาพและตำแหน่ง
       - รับเรื่องร้องเรียนเข้าสู่การดำเนินการ
   
   2.3 การอัพเดทความคืบหน้า
       - เปลี่ยนสถานะเรื่องร้องเรียน (รอดำเนินการ > กำลังดำเนินการ > เสร็จสิ้น)
       - เพิ่มความคิดเห็นและรายละเอียดการดำเนินงาน
       - แนบรูปภาพประกอบการแก้ไข (Before/After)
       - แจ้งปิดงาน (เสร็จสิ้น) พร้อมระบุสรุปการแก้ไข
       - ส่งต่อเรื่องร้องเรียนไปยังหน่วยงานอื่น (หากเกี่ยวข้องและจำเป็น)
   
   2.4 การรายงาน
       - ดู Dashboard ภาพรวมของระบบ
         > สถิติเรื่องร้องเรียนทั้งหมด
         > จำนวนตามสถานะ (รอดำเนินการ, กำลังดำเนินการ, เสร็จสิ้น, ยกเลิก)
         > จำนวนตามประเภทปัญหา
         > จำนวนตามหน่วยงานที่รับผิดชอบ
         > สถานที่ที่มีปัญหาบ่อยที่สุด (Top 10)
       - ดูกราฟและแนวโน้ม
         > กราฟเรื่องร้องเรียนรายเดือน/รายปี
         > อัตราการแก้ไขปัญหา (%)
         > ระยะเวลาเฉลี่ยในการแก้ไขปัญหา
         > การเปรียบเทียบข้อมูลระหว่างช่วงเวลา
       - ดูสถิติงานของตนเอง (จำนวนงานที่ได้รับ ดำเนินการ เสร็จสิ้น)
       - ดูระยะเวลาเฉลี่ยในการแก้ไขปัญหา
       - Export รายงานงานประจำเดือน

3. ผู้ดูแลระบบ (Admin) - ศูนย์สารสนเทศ
   
   3.1 การจัดการผู้ใช้งาน
       - เพิ่ม/ลบ/แก้ไขข้อมูลผู้ใช้งานทุกประเภท
       - กำหนดบทบาทและสิทธิ์การเข้าถึง (Role-Based Access Control)
       - ระงับหรือเปิดใช้งานบัญชีผู้ใช้
       - รีเซ็ตรหัสผ่านให้ผู้ใช้งาน
       - ดูรายการผู้ใช้งานทั้งหมดพร้อมสถานะ
   
   3.2 การจัดการเรื่องร้องเรียน
       - ดูเรื่องร้องเรียนทั้งหมดในระบบ
       - มอบหมายงานไปยังเจ้าหน้าที่ที่เกี่ยวข้อง (กรณีระบบไม่สามารถมอบหมายอัตโนมัติได้)
       - เปลี่ยนลำดับความสำคัญของเรื่องร้องเรียน
       - ย้ายเรื่องร้องเรียนไปยังหน่วยงานอื่น
       - ลบหรือระงับเรื่องร้องเรียนที่ไม่เหมาะสม
       - ดูประวัติการดำเนินการทั้งหมด
   
   3.3 การจัดการประกาศและข่าวสาร
       - สร้าง/แก้ไข/ลบประกาศและข่าวสาร
       - กำหนดวันที่เริ่มต้น-สิ้นสุดการแสดงประกาศ
       - กำหนดระดับความสำคัญของประกาศ (ทั่วไป, สำคัญ, ด่วนมาก)
       - แนบรูปภาพหรือเอกสารประกอบประกาศ
       - ส่ง Push Notification ไปยังผู้ใช้งาน (ทั้งเว็บและ LINE)
       - ดูสถิติการเข้าชมประกาศ
   
   3.4 การจัดการระบบตำแหน่ง
       - เพิ่ม/แก้ไข/ลบข้อมูลอาคาร
       - เพิ่ม/แก้ไข/ลบข้อมูลชั้น
       - เพิ่ม/แก้ไข/ลบข้อมูลห้อง/พื้นที่
       - อัพโหลดและจัดการแผนที่มหาวิทยาลัย (map.png)
       - กำหนดความสัมพันธ์ระหว่างอาคาร-ชั้น-ห้อง
   
   3.5 การจัดการหมวดหมู่และหน่วยงาน
       - เพิ่ม/แก้ไข/ลบหมวดหมู่ปัญหา
       - เพิ่ม/แก้ไข/ลบหน่วยงานที่รับผิดชอบ
       - กำหนดความเชื่อมโยงระหว่างหมวดหมู่กับหน่วยงาน (Auto-assignment Rules)
   
   3.6 Dashboard และรายงาน
       - ดู Dashboard ภาพรวมของระบบ
         > สถิติเรื่องร้องเรียนทั้งหมด
         > จำนวนตามสถานะ (รอดำเนินการ, กำลังดำเนินการ, เสร็จสิ้น, ยกเลิก)
         > จำนวนตามประเภทปัญหา
         > จำนวนตามหน่วยงานที่รับผิดชอบ
         > สถานที่ที่มีปัญหาบ่อยที่สุด (Top 10)
       - ดูกราฟและแนวโน้ม
         > กราฟเรื่องร้องเรียนรายเดือน/รายปี
         > อัตราการแก้ไขปัญหา (%)
         > ระยะเวลาเฉลี่ยในการแก้ไขปัญหา
         > การเปรียบเทียบข้อมูลระหว่างช่วงเวลา
       - Export รายงาน
         > Export เป็นไฟล์ PDF
         > Export เป็นไฟล์ Excel
         > กรองข้อมูลตามช่วงเวลา ประเภท สถานะ หน่วยงาน
   
   3.7 การตั้งค่าระบบ Template
       - ตั้งค่าข้อมูลพื้นฐานมหาวิทยาลัย (ชื่อ, โลโก้, ข้อมูลติดต่อ)
       - กำหนดสีธีม (Theme Color) ของระบบ
       - ตั้งค่า Configuration File สำหรับสถาบันอื่น
       - Import/Export ข้อมูล Configuration

ข้อกำหนดเชิงไม่หน้าที่ (Non-functional Requirements)
--------------------------------------------------------------------------------

1. ประสิทธิภาพ (Performance)
   • ระบบต้องสามารถรองรับผู้ใช้งานพร้อมกันอย่างน้อย 30,000 คนโดยไม่ล่ม
   • เวลาตอบสนอง (Response Time) ไม่เกิน 3 วินาทีต่อการร้องขอ
   • การโหลดหน้าเว็บไซต์ไม่เกิน 5 วินาที

2. ความปลอดภัย (Security)
   • ใช้ JWT สำหรับ Authentication และ Authorization
   • ข้อมูลรหัสผ่านต้องถูกเข้ารหัสด้วย Hashing Algorithm (bcrypt)

3. การใช้งานง่าย (Usability)
   • ระบบต้องรองรับการใช้งานผ่านอุปกรณ์ Desktop และ Mobile
   • อินเทอร์เฟซต้องใช้งานง่าย ไม่ซับซ้อน เหมาะกับผู้ใช้ทุกวัย
   • มีคู่มือการใช้งานและ Tutorial สำหรับผู้ใช้งานใหม่
   • ใช้ภาษาไทยที่เข้าใจง่ายและชัดเจน

4. การบำรุงรักษา (Maintainability)
   • โครงสร้างโค้ดต้องแยกส่วนชัดเจน (Modular) เพื่อให้ปรับปรุงง่าย
   • ต้องมีเอกสารอธิบาย API Documentation (Swagger) และโครงสร้างระบบ

5. ความสามารถในการขยายระบบ (Scalability)
   • ระบบต้องสามารถเพิ่มจำนวนผู้ใช้งานและฟังก์ชันใหม่ได้โดยไม่กระทบต่อประสิทธิภาพหลัก
   • สามารถเพิ่มฟังก์ชันใหม่ได้โดยไม่ต้องแก้ไขโครงสร้างหลัก
   • Database ต้องออกแบบให้รองรับการขยายข้อมูล

3.1 สถาปัตยกรรมระบบ (System Architecture)
================================================================================

ระบบจะถูกพัฒนาในรูปแบบ Web Service โดยมีการแบ่งออกเป็น 3 ชั้นหลัก ได้แก่

• Frontend Layer
  พัฒนาโดยใช้ React + Vite พร้อม Tailwind CSS สำหรับจัดการ UI และ SWC สำหรับคอมไพล์โค้ด

• Backend Layer
  ใช้ Node.js ร่วมกับ Express.js ในการจัดการ API และเชื่อมต่อฐานข้อมูล พร้อม JWT สำหรับการตรวจสอบสิทธิ์

• Integration Layer
  เชื่อมต่อกับบริการภายนอก เช่น LINE Messaging API, Firebase Cloud Messaging สำหรับการแจ้งเตือน

ระบบจะรองรับการทำงานแบบ Responsive Design เพื่อให้สามารถใช้งานได้ทั้งบนคอมพิวเตอร์และอุปกรณ์พกพา


3.2 Use Case Diagram
================================================================================

Use Case Diagram จะแสดงความสัมพันธ์ระหว่างผู้ใช้งานแต่ละกลุ่มกับฟังก์ชันหลักของระบบ โดยแบ่งเป็น 3 กลุ่ม

• ผู้ร้องเรียน
  ส่งเรื่องร้องเรียน, ติดตามสถานะ, รับแจ้งเตือน, ใช้งานผ่านเว็บไซต์หรือ LINE Bot

• เจ้าหน้าที่ผู้รับผิดชอบ
  รับมอบหมายงาน, อัพเดทสถานะ, เพิ่มความคิดเห็น, จัดการลำดับความสำคัญ

• ผู้ดูแลระบบ
  จัดการผู้ใช้งาน, สร้างประกาศ, ดูรายงานสถิติ, กำหนดสิทธิ์การเข้าถึง


3.3 Data Schema (NoSQL/SQL)
================================================================================

ระบบจะใช้ฐานข้อมูลแบบ NoSQL โดยเลือกใช้ MongoDB เป็นหลักในการจัดเก็บข้อมูล โดยมีโครงสร้างข้อมูลหลัก ได้แก่

• Users
  ข้อมูลผู้ใช้งาน เช่น ชื่อ, อีเมล, บทบาท, Token

• Complaints
  รายละเอียดเรื่องร้องเรียน เช่น หมวดหมู่, ความเร่งด่วน, ตำแหน่ง, รูปภาพ, สถานะ

• Announcements
  ข่าวสารและกิจกรรมที่เผยแพร่

• Statistics
  ข้อมูลสถิติสำหรับการวิเคราะห์และแสดงบน Dashboard


3.4 Report Microservices Architecture Design (Server Services)
================================================================================

ระบบรายงานจะถูกแยกออกเป็น Microservice เพื่อรองรับการวิเคราะห์ข้อมูลและการสร้างรายงาน โดยมีฟังก์ชันหลัก

• ดึงข้อมูลเรื่องร้องเรียนตามช่วงเวลา
• สรุปจำนวนเรื่องร้องเรียนตามหมวดหมู่และสถานะ
• คำนวณอัตราการแก้ไขและระยะเวลาเฉลี่ย
• Export รายงานเป็น PDF หรือ Excel


3.5 Report API Checklist
================================================================================

### Complaints
| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | /api/complaints | ดึงรายการเรื่องร้องเรียนทั้งหมด (มี filter) |
| GET | /api/complaints/:id | ดึงเรื่องร้องเรียนเดียว |
| POST | /api/complaints | สร้างเรื่องร้องเรียนใหม่ |
| PUT | /api/complaints/:id | อัพเดทเรื่องร้องเรียน |
| DELETE | /api/complaints/:id | ลบเรื่องร้องเรียน |

### Locations
| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | /api/locations/buildings | ดึงรายการอาคาร |
| GET | /api/locations/floors/:building | ดึงรายการชั้นของอาคาร |
| GET | /api/locations/rooms/:building/:floor | ดึงรายการห้อง |
| POST | /api/locations | สร้างตำแหน่งใหม่ (Admin) |

### Categories
| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | /api/categories | ดึงรายการหมวดหมู่ |
| POST | /api/categories | สร้างหมวดหมู่ใหม่ (Admin) |

### Upload
| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | /api/upload | อัพโหลดรูปภาพ (สูงสุด 5 รูป) |
